# Grill: observability and cost guardrails

## Question

Which CloudWatch alarms and budget guardrails does the polls stack define, and what do they notify? Decide with the human: alarms on function URL `Url4xxCount`/`Url5xxCount` and `Throttles`, `ConcurrentExecutions` at the reservation of 2 (the documented fallback if a throttled function URL request does not move the 4xx or throttle metrics), Lambda `Errors`, DynamoDB write failures (system errors, throttled requests), and WAF blocks from the rate rule (the ACL already emits CloudWatch metrics per rule); thresholds and evaluation periods; where notifications go (an SNS topic with an email subscription, or nothing); a budget alert for the account or the polls stack; log retention for the Lambda log group; and how alarms are covered by the golden test. Context: [Grill: abuse limits](06-grill-abuse-limits.md) (metric evidence and the open inference about 429 counting), [Grill: repo and deployment layout](07-grill-repo-deployment-layout.md) (alarms live in `stack/polls.py`), [Decide: architecture](04-decide-architecture.md), research/06 for unit prices.

## Resolution

Confirmed by the human at the end of the grilling session. The ticket's original question assumed alarms and notifications; the human redirected to a manual, periodic check from cheap long-term storage, with filtering and normalization deferred to a later phase. Prices, facts and decisions:

Prices looked up (aws-pricing MCP, us-east-1, Price List API): CloudWatch standard alarm $0.10 per alarm metric month (`AmazonCloudWatch`, usagetype `CW:AlarmMonitorUsage`, SKU EVETVUGEN3MUTMXM); SNS email: first 1,000 notifications per month free, then $2.00 per 100,000 (`AmazonSNS`, usagetype `DeliveryAttempts-SMTP`, SKU BZ4UZ2ERDQACBPJ4), first 1,000,000 API requests free (`Requests-Tier1`, SKU QDX8G2WMY9NPXXPG); Budgets notifications listed at $0.00 per budget-day (`AWSBudgets`, usagetype `BudgetsUsage`, SKU T2UVJ9XYT52FBFAF; free-tier budget count not in the API result).

Logging facts (aws-docs MCP): WAF can deliver web ACL logs to CloudWatch Logs, Amazon S3 or Firehose, with S3 delivery charged as CloudWatch vended-log delivery plus S3 (https://docs.aws.amazon.com/waf/latest/developerguide/logging-pricing.html, https://docs.aws.amazon.com/waf/latest/developerguide/logging-destinations.html); destination names must begin with `aws-waf-logs-`. CloudFront standard logging (v2) can deliver to S3 with no additional CloudFront charge, only S3 storage and access fees (https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/standard-logging.html).

0. **Direction change by the human:** no automated alerting is needed. The need is a way to manually and periodically check for problems, ideally a log of admin events in cheap, long-term storage. This supersedes the SNS/email and alarm-threshold parts of the ticket's question (alarms and a notification topic are not wanted for now).
1. **Log contents (sources):** option B. Handler events plus CloudFront access logs in S3 (CloudFront delivers to S3 with no extra CloudFront charge). **Refined by the human:** it must not be a raw log dump; it must be filtered to events that require admin attention (analogous to syslog WARN/ERROR), and formats must be normalized across sources so Athena queries are simple. Intended for periodic manual checks, in cheap long-term storage. Personal data: the handler never logs email or answer text; CloudFront records include client IP (`c-ip`), so retention for that source needs a limit.

Facts checked (aws-docs MCP): CloudFront standard logging v2 to S3 supports JSON, plain, w3c, raw and Parquet output, set only when the delivery destination is created (cannot be changed later; recreate to change); supports date partitioning and Hive-compatible paths (https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/standard-logging.html). Records have 33 fields including `sc-status`, `c-ip`, `cs-method`, `cs-uri-stem`, `x-edge-result-type` (`Error` typically means a 4xx or 5xx); delivery is up to several times an hour and can be delayed up to 24 hours (https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/standard-logs-reference.html). Not confirmed: that WAF-blocked requests appear as 403 with result type `Error` (inference; only the first 16 of 33 fields were read).
2. **Phasing (human reconsidered decision 1's filtering):** filtering and normalization across sources are deferred to a later phase. For now: raw CloudFront access logs delivered to S3 with source-specific Athena queries (AWS documents ready-made Athena table definitions with partition projection for CloudFront v2 logs in JSON and Parquet: https://docs.aws.amazon.com/athena/latest/ug/create-cloudfront-table-partition-json.html, https://docs.aws.amazon.com/athena/latest/ug/create-cloudfront-table-partition-parquet.html). The data models are examined later to decide whether and how to filter and normalize. No alarms and no notification topic (supersedes the ticket's original SNS/alarm-threshold question; any budget alert is also an automated notification and is dropped unless the human asks for it).
3. **Handler events:** stay in CloudWatch Logs for now. The handler writes structured JSON lines (never email or answer text) to its log group with a long retention period set, queried with CloudWatch Logs Insights; Athena covers CloudFront only in this phase. Rejected for now: on-demand export to S3 via `CreateExportTask` (https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/S3ExportTasks.html; adds a manual script and files mixing Lambda platform lines with handler lines; latency and limits not read); continuous streaming via a subscription filter and Firehose, or direct S3 writes by the handler (more infrastructure; per-event request cost grows during a flood). Cost of this choice: two query tools for two sources until the later phase.
4. **CloudFront log bucket:** JSON output (readable by eye; format cannot be changed after the delivery is created, so a change means recreating it), 365-day expiration lifecycle rule, S3 Standard, no storage-class transitions (savings negligible at this size). Retention is a privacy choice, not a cost one: records contain client IPs (`c-ip`); S3 Standard is $0.023/GB-month (research/06). Rejected: Parquet (unreadable without Athena; no benefit at megabyte scale); no expiration (keeps visitor IPs indefinitely). Revisit the format in the later data-model phase if needed.
5. **Handler log group retention:** 365 days (matches the CloudFront bucket so both sources cover the same window; the handler logs contain no email or answer text, so the privacy argument for a shorter window is weaker). A Lambda log group otherwise never expires by default. CloudWatch Logs rates: $0.50/GB ingested, about $0.03/GB-month stored (research/06). Rejected: 90 days; never expire. If the later phase moves handler events into S3, expiration there is set independently.
6. **Athena side in the stack:** all in `PollsStack`: Glue database and table for the CloudFront logs (columns and partition projection per the AWS-documented JSON DDL), an Athena workgroup with a results location that expires after about 30 days, saved Athena queries for the routine check (errors by day, top client IPs, 403s and 429s), and matching saved CloudWatch Logs Insights queries for the handler. All covered by the golden test. Rejected: table and workgroup without saved queries; a script that runs the DDL outside CloudFormation (drift risk). Athena costs $5 per TB scanned (research/06); these logs are megabytes. The saved queries double as the first draft of the data model examined in the later phase.

Implementation facts and open items (aws-iac MCP, aws-cdk-lib 2.273.0 docs): CloudFront standard logging v2 is configured in CDK through the `aws_logs` L1s (`CfnDeliveryDestination` with `delivery_destination_type="S3"`, plus a source and a delivery); the docs example creates an explicit `BucketPolicy` on the destination bucket to allow delivery (https://constructs.dev/packages/aws-cdk-lib/v/2.273.0/api/CfnDeliveryDestination?lang=python&submodule=aws_logs). A preview `@aws-cdk/mixins-preview` package (alpha) also offers a `CfnDistributionLogsMixin`; the example found covered connection logs, so whether an access-log mixin exists was not confirmed. Not verified: the L1 property that sets the JSON output format and the exact bucket-policy statements needed. The repo pins `aws-cdk-lib==2.260.0` in `requirements.txt` (docs read were 2.273.0), so confirm the L1s exist in the pinned version.
